# Evolving Benchmark

Evolving Benchmark is a Rust CLI for repeatable AI model benchmarks. **Decision Benchmark** is the first module. It compares models on structured decisions in agent workflows: tool selection, model routing, guardrails, delegation, confidence escalation, and stop/continue behavior.

Model discovery and calls use an OpenRouter adapter. The catalog is fetched when you run a command; benchmark results are snapshots from an individual run and do not update until you run it again.

## Requirements

- Rust 1.87 or later and Cargo
- An OpenRouter API key for `run` and `resume`

Set the key in the environment or copy `.env.example` to `.env` and add the key. Never pass it as a command-line argument. The `.env` file is git-ignored.

## Build and test

```powershell
cargo build --release
cargo test --all-targets
cargo run -- --help
```

The automated test suite uses mock HTTP responses and does not spend API credits.

## Commands

```powershell
cargo run -- catalog decision --config examples/benchmark.toml
cargo run -- plan decision --config examples/benchmark.toml --budget-usd 5
cargo run -- run decision --config examples/benchmark.toml --budget-usd 5
cargo run -- resume <run-id>
cargo run -- report <run-id>
```

`catalog` lists candidate and excluded models with reasons and saves a catalog snapshot. `plan` estimates the maximum request spend before sending model requests. `run` requires the same explicit budget and writes a run manifest, catalog snapshot, and append-only per-call JSONL results under `runs/<run-id>/`. `resume` skips successful, priced calls from an interrupted run. `report` writes Markdown, overall CSV, and scenario CSV outputs.

## Configuration

`examples/benchmark.toml` documents the configuration format. The initial suite is `decision/full` (30 cases across six scenarios), with repeat count, concurrency, request-size/output-token caps, retry count, model spacing, and catalog filters configurable there.

By default, candidates must support text input/output and structured output, have known prompt and completion prices within the configured maximums, and satisfy the minimum context and freshness filters. `creators` filters model authors locally; `providers` filters the catalog request at OpenRouter; `required_parameters` checks advertised API parameters. Use `include`/`exclude` to control exact model IDs. Explicit inclusion does not bypass protocol requirements or cost-budget checks. To use the OpenRouter Decisions API for a model with that protocol, set a protocol override:

```toml
[protocol_overrides]
"typesafe/jev-1.13" = "openrouter_decisions"
```

The API catalog exposes pricing per token; the CLI normalizes it to USD per million tokens for display. Planning uses a conservative UTF-8 byte-based upper bound, configured `max_input_bytes` and `max_output_tokens`, and reserves for each configured retry. Retry spend is accounted with a per-attempt estimate; successful-call usage from OpenRouter remains separately recorded. A call with unknown reported cost halts scheduling. Ranking is blocked for incomplete coverage or missing/invalid costs. Provider price changes or post-run billing adjustments can differ from catalog estimates; the manifest and per-call usage preserve what the runner observed.

## Results and reproducibility

Each run records requested and resolved model IDs, dataset/scoring versions, catalog snapshot, effective secret-free configuration, randomization seed, concurrency, costs, latencies, token usage, errors, and run status. Results are stored as JSONL so each completed call is flushed to disk. Run IDs can be used with `resume` and `report`.

Decision v1 reports exact-match accuracy, valid output, JSON format compliance where applicable, mean cost, end-to-end latency, per-scenario metrics, and the existing versioned combined score. Reports do not assume a known model roster.

## Historical Python benchmark

The Python implementation and checked-in outputs are retained as historical material from the earlier Classifier Benchmark run. Existing CSV/model lists and reports are not the source of candidates for new Rust runs. In particular, the files `models.csv`, `results.jsonl`, `benchmark.py`, `run_benchmark.py`, and `retry_failed.py`, along with the current `artifacts/`, were produced before the Rust CLI and should not be compared as if generated by the same runner version.

The historical run used 16 models, 30 cases, and five starts per model/case. Its old reports contain model-specific analysis and do not represent current OpenRouter availability.
